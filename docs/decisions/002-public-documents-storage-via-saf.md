# 002：数据存放在公共 Documents 文件夹，通过自写 SAF 插件读写

日期：2026-10-31。状态：已采用。

## 背景

孩子的听写和错题记录要积累很长时间。如果 App 被误卸载，数据不能丢。所以数据放在公共的 `Documents/smartstudy` 文件夹，由用户通过系统文件夹选择器（SAF）授权读写：卸载后文件仍在，重装后重新授权即可继续使用。

Capacitor 官方 Filesystem 插件做不到这一点。它的 `Directory.Documents` 在 Android 11 及以上只能访问本 App 自己创建的文件（[文档](https://capacitorjs.com/docs/apis/filesystem)）。卸载重装后系统把新装的 App 当成另一个应用，旧文件就读不到了。两台目标设备都在 Android 11 以上。

## 决定

写一个只在本项目使用的 Capacitor Android 插件（Java），放在 `android/` 工程里注册，不发布 npm 包。插件只封装 SAF：

| 接口 | 作用 |
|---|---|
| `getFolder()` | 返回已授权的文件夹及授权是否仍然有效 |
| `pickFolder()` | 打开系统选择器；用户选 `Documents` 时自动创建并使用 `smartstudy` 子文件夹，持久保存授权 |
| `readText(path)` | 读取文件夹内的相对路径，文件不存在时返回空 |
| `writeText(path, text)` | 写入文件，不存在的上级目录自动创建 |
| `list(path)` / `remove(path)` / `rename(path, newName)` | 管理历史版本和临时文件；`rename` 只在同一文件夹里改名 |

JS 侧在插件之上实现一个存储层（`src/storage/`），App 用这个插件，电脑浏览器用 File System Access API，测试用内存实现。三者接口相同，业务代码不区分平台。

存储服务的规则：

- **防止写坏**：先写 `<文件>.tmp`，读回并解析成功后，把新版本也存一份到 `history/`（历史里还没有当前正式文件时，先把它存进去），再删掉旧的正式文件，把临时文件改名为正式文件。这样 `history/` 里最新的版本总是最后一次保存，正式文件以后被改坏时，恢复不会少掉最近一次学习。启动时如果发现正式文件缺失但临时文件有效，就用临时文件恢复。写入时用 fsync 把数据真正写到存储上，再删旧文件，断电也不会两份都坏。正式文件损坏或缺失、改用临时文件或历史版本时，先把损坏的文件另存为 `history/…/<时间>.broken`（不是 UTF-8 编码的文件按 UTF-8 读会丢字节，所以原样改名为同目录下的 `<文件名>.<时间>.broken`），再把恢复用的版本写回正式文件，所以恢复只发生一次。读文件时严格按 UTF-8 解码，解不了的当作损坏，不会把乱码存回去。每次读写都带上打开时的文件夹标识，换了文件夹以后，还在进行的旧文件夹读写会被拒绝，不会写进新文件夹。保存前还核对文件和上次读到或写入时是否一样：在别处被改过（例如另一个浏览器窗口，或从电脑拷了进来）就不保存，提示重新打开 App，不会用旧数据盖掉别处写入的数据。电脑上同一个文件夹开了几个浏览器窗口时，读写用浏览器的 Web Locks 轮流进行，两个窗口不会同时写同一个临时文件。Web Locks 只在同一个浏览器、同一个网址的窗口之间有效；Android 上 debug 包和正式包之间、电脑上两个浏览器之间没有这种互斥，所以每次改名后再读一次正式文件，内容不是这次保存的（被另一个 App 同时写过）就报错，不当作已保存，本次运行也不再写这个文件。App 开着时数据文件夹被改名或移走，读写会报“数据文件夹不存在了”，不会把文件当成缺失、显示成空的。`.broken` 文件不算历史版本，不会被自动清理，方便手动修复。临时文件或历史版本来自更新的 App 版本时，同样不加载、不覆盖。
- **历史版本**：文件名是保存时刻（UTC，例如 `20261031-121503-123.json`），并且总比这个文件已有的历史版本名更晚，所以设备时间被调回或换了时区，顺序也不会乱，已有的历史版本也不会被覆盖。每个数据文件保留最近 10 个版本，另外保留最近 30 个有保存的日子（UTC 日期，按文件名算）里每天的最后一个版本，所以某次保存时设备时间被调到很久以后，也不会把之前每天的版本都当成过期删掉。时间被调回以后，到真实时间追上之前保存的版本都算作同一天。一次用户操作（例如编辑后保存）只写一次文件。一个孩子用了一年的数据文件约 0.25–0.4 MB，每个文件的历史最多约 40 份，合计十几 MB。
- **文件格式**：每个数组元素占一行，比缩进格式小约 40%，仍然可以在电脑上直接阅读和比较。
- **不认识的格式不碰**：`schema` 版本更高或名字不认识的文件，既不加载也不覆盖，也不改用旧版本。`app.json` 和 `settings.json` 的修改同样排队、校验后才写入。
- **按用户和数据类型拆分文件**：单个文件损坏只影响一部分数据。
- **启动时一次读入内存**：之后在内存里修改，写入串行进行，避免快速操作时新数据被旧数据覆盖。
- **写入前先校验**：修改后的数据先用读取时的同一套校验检查，通不过就不写；写入的是校验后的值，字段顺序和读取结果一致，所以撤销一次操作后，文件与操作前逐字节相同（这次听写里改过的英语译文除外，见数据约定）。
- **华为设备兼容**：华为设备上可能无法自动创建 `smartstudy` 子文件夹。这时提示用户先手动新建这个文件夹，再选择它。

## 被放弃的方案

- **数据放在 App 私有目录，再自动备份到 Documents**：不需要原生代码。但重装后的 App 无法覆盖或删除旧备份文件，恢复时还要手动选择备份文件，同时存在两份数据。
- **申请"所有文件访问"权限（MANAGE_EXTERNAL_STORAGE）**：属于敏感权限，容易触发厂商安全提示，开源后别人使用也不合适。
- **IndexedDB 或 Preferences**：数据在 App 私有目录里，卸载即丢失。

## 影响

- 项目里有一小段需要维护的原生代码（`SafFolderPlugin.java`，用 Java 编写）。它只依赖 Android 系统 API，没有第三方二进制文件。
- 已用 `tools/smoke_android.mjs` 在 Android 16 模拟器上验证，也在 MatePad 11 上手动验证过：授权 Documents → 读取已有数据 → 写入 → 卸载后文件仍在 → 重装并重新授权后数据完整 → 冷启动不再询问。MatePad 上 `smartstudy` 文件夹已存在，可以直接选择。
- 用户可以直接在文件管理器里看到数据，也可以用 USB 拷到电脑备份，或者拷到电脑上用浏览器打开。
- API Key 不放在这个公共文件夹里，因为其他有存储权限的 App 也能读取。
